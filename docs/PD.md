## 1. 产品概述

### 1.1 背景

弘盛非洲机电内部需要一套轻量、可维护的仓库管理工具。系统采用 **React（Next.js）** 作为界面，**FastAPI** 在本地提供 API（复用 `db_manager.py`），通过 **pywebview** 嵌入原生窗口，最终 **PyInstaller 打包为 exe** 分发。

> **不是浏览器 Web 版**：不部署到内网服务器；用户双击 exe，本地启动 API + 桌面窗口，无需安装 Python 或 Node。

### 1.2 产品定位

| 维度 | 说明 |
|------|------|
| 目标用户 | 弘盛非洲机电仓管人员（内部） |
| 使用场景 | 办公室 Windows PC，双击 exe |
| 界面技术 | React + Tailwind（`frontend/`） |
| 核心价值 | 现代 UI、单机可用、业务逻辑不变 |

### 1.3 产品目标

1. **React 界面**：用 Web 技术栈做 UI，体验优于传统 PyQt6 表单。
2. **单机 exe**：pywebview 窗口 + 本地 FastAPI，不依赖外网与浏览器标签页。
3. **逻辑稳定**：库存以 `current_stock` 为准；共用 `db/honsen_storage.db`。
4. **易维护**：UI（React）与业务（`db_manager.py`）分离。

### 1.4 非目标（Out of Scope — v1）

- 多仓库 / 多租户 SaaS
- 移动端原生 App
- 与 ERP / 财务系统对接
- 条码枪 / RFID 硬件集成
- 导入历史交易并自动改库存
- 多角色权限体系（v1 仅管理员）

## 3. 核心业务规则

> [WARN] 以下规则为系统铁律，桌面版必须遵守，不得弱化。

### 3.1 库存哲学

- **当前库存量（`current_stock`）是权威数据。**
- 交易记录是辅助追踪，用于审计与查询。
- **库存变动必须经正式出入库操作**；导入交易记录不会自动增减库存。

### 3.2 数据录入准则

1. **类目唯一**：同一类物品归一个类目，禁止多头定义。
2. **条目唯一**：组合键 `(名称, 型号, 存放位置, 柜号)` 唯一。
3. **避免分散储存**：同一物品尽量不分散多地点，降低盘点难度。
4. **备注规范**：出入库用途写在「接收人/来源」或项目字段。

### 3.3 库存变动途径

| 途径 | 是否改变库存 | 说明 |
|------|-------------|------|
| 入库 IN | [OK] 增加 | 正式操作 |
| 出库 OUT | [OK] 减少 | 正式操作，需校验库存 |
| 冲销 REVERSAL | [OK] 反向调整 | 生成新记录，保留原记录 |
| 删除交易 | [OK] 回滚 | 禁止删除冲销类记录 |
| 编辑交易 | [OK] 差额调整 | 禁止编辑冲销类记录 |
| CSV 导入库存 | [OK] 覆盖/新增 | 按组合键 upsert |
| CSV 导入交易 | [ERR] v1 不支持 | — |

### 3.4 库存状态计算

| 状态 | 条件 |
|------|------|
| 缺货 | `current_stock ≤ 0` |
| 预警 | `0 < current_stock ≤ min_stock` |
| 正常 | `current_stock > min_stock` |

## 5. 数据模型摘要

### 5.1 Inventory（库存）

```
id, name, reference, category, domain, unit,
current_stock, min_stock, location, cabinet
```

唯一约束：`(name, reference, location, cabinet)`

- `cabinet`：仓库**柜号**，与 `location` 一起标识货位；仅在新增/编辑库存时维护。
- 同一 `(name, reference, location, cabinet)` 仅一条库存记录。

### 5.2 transactions（交易）

```
id, item_id, date, type, quantity, recipient_source, project_ref
```

类型枚举：`IN` | `OUT` | `REVERSAL-IN` | `REVERSAL-OUT`

- `recipient_source`：入库时为**来源柜号**；出库时为**接收人**。
- 交易列表「柜号」列：入库显示来源柜号（`recipient_source`），出库显示库存柜号（`Inventory.cabinet`）。

### 5.3 config（配置）

```
id, category, value
```

category 枚举：`LOCATION` | `PROJECT` | `UNIT` | `CATEGORY` | `DOMAIN`

### 5.4 admin_user（管理员）

```
id, username, password(SHA256 hex)
```

## 6. 系统架构

```
desktop/launcher.py（exe 入口）
    ├─ pywebview 窗口 → http://127.0.0.1:8000/
    └─ uvicorn → FastAPI (backend/)
            ├─ /api/*  REST + JWT
            └─ /       静态 React（frontend/out）
                    ↓
            db_manager.py + data_utility.py
                    ↓
            SQLite (exe 同目录 db/honsen_storage.db)
```

### 6.1 技术选型

| 层 | 技术 | 理由 |
|----|------|------|
| UI | React、Next.js、TypeScript、Tailwind | 现代组件化、易改版 |
| 桌面壳 | pywebview（系统 WebView2） | 轻量，与 PyInstaller 配合好 |
| API | FastAPI、Pydantic、uvicorn | 复用 Python 业务层 |
| 业务 | `db_manager.py` | 历史沿用的业务层（PyQt6 版已下线） |
| 数据库 | SQLite | 单文件备份 |
| 打包 | PyInstaller | 单 exe 分发 |

### 6.2 开发与发布

| 模式 | 命令 |
|------|------|
| 前端热更新 | `uvicorn` + `npm run dev`（:3000 → :8000 API） |
| 桌面预览 | `npm run build:desktop` → `python desktop/launcher.py` |
| 正式发布 | `scripts/build-desktop.ps1` → `dist/Honsen WMS.exe` |

PyQt6 旧版代码已随本次清理下线（不再保留于仓库，历史版本见 Git 记录）。
